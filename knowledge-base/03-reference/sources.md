# Sources

Annotated index of external references that have shaped this vault. New external material can land here directly if it's already a stable reference, or get captured into `[[00-inbox]]` first if it needs triage.

## Markup formats and specs

- **[Markdoc — Overview](https://markdoc.dev/docs/overview)** — Stripe's structured markdown format. Tag syntax `{% tag %}`, schema-validated, designed for embedded structured content in long-form prose. Central artifact for the embedded-markup vs HTML-in-markdown debate. Discussed in [[markdoc-vs-shortcode-systems]].

## Philosophy / first principles

- **[BGS Labs — Why are we using markdown?](https://bgslabs.org/blog/why-are-we-using-markdown/#solution)** — Argument for markdown as a durable authoring substrate. The "#solution" section is worth reading for the framing of *why* plain markdown survives where richer formats don't.

## How sources progress

External references can move through the gradient too:

1. **`00-inbox/`** — a fresh link with a one-line "why I saved this" note. Capture cheap, decide later.
2. **This file (`03-reference/sources.md`)** — promoted when a source has clearly earned a durable spot in the vault's reference layer.
3. **`02-learnings/`** — when a source produces an atomic insight, the *insight* becomes a learning; the source stays here as the citation.
4. **`04-archive/`** — superseded or no-longer-relevant sources get archived rather than deleted (history is cheap).

Wikilink to sources from learnings and working notes rather than restating them.
